Content Refresh Signals and Action Prioritization

Author: Sulamith Singh

Abstract

This project studies content-refresh signals in the FlyRank starter dataset and develops a decision-support workflow for prioritizing pages for human review. A Random Forest classifier was trained using days since last update, impressions in the last 90 days, click-through rate, and average search position. A random 80/20 split produced an accuracy of 1.00, while a client-grouped 80/20 validation produced an accuracy of approximately 0.99984 with no client overlap between training and testing sets.

However, the validation audit found an important limitation: the target label was directly constructed from the same four features used by the model. Therefore, the near-perfect model performance should not be interpreted as evidence of general predictive ability. The final analysis focuses on honest validation, observed content patterns, and a ranked action playbook rather than presenting the model as a production-ready predictor.

1. Introduction / Problem Statement

Content teams need a practical way to identify pages that may deserve review or monitoring. This project examines observable search-performance signals such as clicks, impressions, click-through rate, ranking position, content age, and trend direction.

The main goal is to turn these signals into a transparent decision-support workflow. The analysis does not attempt to prove that a specific content change will cause better rankings or traffic.

Research focus

The analysis asks which measurable content and search-performance signals can be used to identify pages that deserve review, and how those signals can be translated into a ranked and human-reviewable action queue.

2. Data

The analysis uses the anonymized FlyRank starter dataset. The dataset contains 30,000 rows and 44 columns.

The modeling workflow uses four features:

  • Days since last update
  • Impressions in the last 90 days
  • Click-through rate (CTR)
  • Average search position

The classification target was defined using four thresholds:

  • days_since_last_update ≥ 90
  • impressions_90d ≥ 1000
  • CTR ≤ 0.10
  • average position ≤ 20
Important data limitation: the target is directly constructed from the four model features. This creates a target-definition problem and means the model is largely learning the rule used to construct its label.

3. Methodology

3.1 Model

A Random Forest Classifier with 100 estimators and random state 42 was used. The model was selected because it can represent nonlinear relationships and provides feature-importance values.

3.2 Initial split

The initial model used an 80/20 train-test split with random state 42. This produced 24,000 training rows and 6,000 test rows.

3.3 Honest validation

A client-grouped 80/20 split was then used to prevent the same client from appearing in both the training and test sets.

4. Results

4.1 Model result

The Random Forest achieved perfect accuracy on the initial random split. Under the more honest client-grouped split, accuracy was 0.9998377. The grouped split also confirmed that no clients appeared in both training and testing sets.

These results are numerically strong but should not be interpreted as evidence that the model will generalize to a real production prediction problem.

4.3 Validation and error analysis

The client-grouped test contained one incorrect prediction. The model predicted 0 while the actual target was 1. The example had 92 days since its last update, 1,130 impressions, a CTR of 0.09, and an average position of 10.0.

This was a false negative. Because the target itself is directly constructed from the model features, this error does not provide enough evidence to make broad claims about model weaknesses.

Leakage / target-definition finding

The target is directly constructed from all four features used by the model. Therefore, the model is learning the rule used to create the target. The near-perfect accuracy should not be treated as general predictive performance.

5. Ranked Recommendations

The final workflow uses observed content-performance segments to create a ranked action queue.

Priority 1 — Striking-distance pages with declining clicks

1,561 pages were identified in this segment, with a median trend of -44.4%.

Recommended action: prioritize human review of factual freshness, content completeness, internal linking, and page/query relevance.

Priority 2 — Impressions but no recent clicks

18,365 pages had impressions but zero clicks in the last 30 days.

Recommended action: investigate indexing, search visibility, title/snippet presentation, ranking position, and page/query relevance before changing content.

Priority 3 — Stable striking-distance pages

823 pages were in this segment, with a median trend of -5.4%.

Recommended action: monitor clicks, impressions, CTR, and average position before making major changes.

Priority 4 — Improving striking-distance pages

489 pages were improving, with a median trend of +54.4%.

Recommended action: avoid unnecessary changes and monitor whether the improvement continues.

6. Limitations and Honest Framing

  • The target is directly constructed from the same four features used by the classifier.
  • The near-perfect accuracy therefore does not demonstrate general predictive performance.
  • The analysis is observational and does not establish causation.
  • The dataset does not contain query text, conversion or revenue data, or all technical SEO and SERP factors.
  • The recommendations are decision-support signals, not guarantees of future performance.
  • Every recommended action should be reviewed by a human before implementation.

8. Monitoring and Future Review

The action playbook should be monitored across reporting periods using the same segment definitions and metrics.

  • Number of pages in each priority segment
  • Clicks in the last 30 days versus the previous 30 days
  • Impressions and CTR
  • Average position
  • Trend direction and trend percentage
  • Changes in segment distribution

A review should be triggered if segment sizes change substantially, trends change materially, important input fields become inconsistent, the schema changes, or the relationship between signals and action priorities changes.
